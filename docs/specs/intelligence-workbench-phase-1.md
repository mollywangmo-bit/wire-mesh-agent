# 丝网行业研报知识库 2.0：Phase 1 实施规格

## 目标与边界

本阶段把既有 Markdown 研报转换为可追溯的独立行业事件，并以事件而非关键词提及次数生成主题趋势。服务仍是主行研 Agent 的独立下游消费者；不得调用或修改主 Agent 的调度、采集、分析、投递与邮件流程。

## 数据模型

- `events`：规范化事件，含事件日期、类型、标题、摘要、证据、置信度、丝网/安平相关性、去重键与创建时间。
- `event_sources`：Event 与报告章节的多对多证据关系；同一事件可有多个来源。
- `themes`：受控主题词表；第一版预置精密过滤、半导体过滤、医疗金属编织、制氢镍网、精密网版、工业过滤、新能源电池网、高性能材料。
- `event_themes`、`event_companies`、`event_regions`：Event 的可查询实体关系。
- `processing_jobs`：每份报告的处理状态与错误信息，支持可重试处理。

## 处理流程

`报告 → 章节 → 候选 Event → 实体/主题 → 去重 → 关系入库 → Trend 计算`。

候选事件先以规则识别（事件动词、行业实体、日期与证据段落）生成，预留 LLM 提取器接口。所有计数、排序、时间窗口比较及最终去重均由确定性代码完成。

## 去重策略

事件指纹由 `事件类型 + 月度时间桶 + 规范化企业 + 地区 + 命中主题` 构成。相同指纹合并为一个 Event，并新增 `event_sources` 证据；`source_count` 是独立报告/章节来源数，不能被转载次数替代。

## 趋势计算

趋势按主题、时间窗口计算独立 Event 数、此前窗口 Event 数、独立企业数、独立地区数、来源数、事件类型多样性和连续性。趋势状态按增长率映射为“快速升温 / 明显上升 / 小幅上升 / 稳定 / 下降”。

## 验收

1. 任一研报可产生多个 Event。
2. 同一事件的重复证据被合并并保留来源。
3. Event 展示类型、主题、企业、区域、证据与来源报告。
4. Trend 排名使用独立 Event；可展开其 Supporting Events。
5. 可比较最近 4 周与此前 4 周。
