# 丝网行业研报知识库工作台（MVP）

## 1. 目标与边界

把既有周报、精简周报和月报转为可检索、可浏览、可追溯的知识资产，并提供基于报告证据的问答与趋势观察。

本工作台是现有行研 Agent 的下游消费者，而不是流水线的一部分：报告推送、采集、LLM 分析和投递维持原有运行节奏。导入或检索失败不得改变原任务的成功状态，也不得阻塞邮件、飞书或企业微信推送。

MVP 面向内部团队，不引入账号体系；部署时应放在已有内网访问控制之后。

## 2. 用户可完成的事

1. 在首页看到累计报告数、最新报告与信号趋势。
2. 按关键词搜索报告片段，查看来源报告和所属章节。
3. 浏览单篇报告的全部章节内容。
4. 查看由报告文本提炼的行业信号趋势：成本/价格、需求、出口、竞争、政策与区域热度。
5. 进行基于报告证据的问答；每个回答均附可回看的报告片段。没有足够证据时明确说明，而不补造结论。

## 3. 信息架构

```text
工作台首页
├─ 最新研报与统计
├─ 趋势信号卡片
├─ 研报中心
│  ├─ 列表与筛选
│  └─ 报告详情 / 章节
├─ 知识搜索
│  └─ 结果片段 / 报告出处
└─ AI 问答
   └─ 检索证据 / 引用来源
```

## 4. 数据流与隔离

```text
现有行研 Agent --(原有投递，完全不改)--> 邮件 / 飞书 / 企业微信
       |
       | 报告归档副本（异步、可重试）
       v
知识库导入器 --> SQLite（MVP） --> 搜索 / 趋势 / 问答 API --> 工作台
```

导入器扫描一个持久化目录中的 Markdown 报告；同一内容使用 SHA-256 去重，可重复执行。生产版本可把 SQLite 换为 PostgreSQL + pgvector，并保留相同的导入契约。

## 5. MVP 数据模型

### reports

报告元信息及全文：`id`、标题、类型、来源路径、内容哈希、导入时间、正文。

### sections

按 Markdown 标题切分的可引用章节：`id`、`report_id`、章节标题、顺序、内容。

### report_signals

每份报告的规则信号计数：`price_cost`、`demand`、`export`、`competition`、`policy`、`regional`。

索引：报告类型、导入时间、章节所属报告和信号名，服务于列表、搜索和趋势查询。

## 6. 核心规则

- 支持 `.md` 文件；标题取一级标题或文件名。
- Markdown 二级及以上标题切分为章节；无标题正文也保留为“正文”。
- 报告类型根据文件名识别为 `weekly`、`weekly_brief` 或 `monthly`。
- 信号趋势是“研报提及变化”，不是外部市场实时价格或统计口径数据；界面必须如此标注。
- 问答先检索匹配章节，再返回审慎摘要和最多三条引用。MVP 不调用外部模型，确保不含未被报告支持的新事实；后续可替换为带引用约束的 RAG 模型。

## 7. API（MVP）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/health` | 服务与数据库健康检查 |
| GET | `/api/reports` | 报告列表 |
| GET | `/api/reports/{id}` | 报告及章节 |
| GET | `/api/search?q=` | 章节级关键词搜索 |
| GET | `/api/trends` | 信号趋势聚合 |
| POST | `/api/ask` | 基于检索证据的问答 |
| POST | `/api/import` | 扫描归档目录并增量导入 |

导入接口在设置 `WIRE_MESH_KB_ADMIN_TOKEN` 后必须使用 Bearer Token；未设置时仅建议在受控内网中使用。

## 8. 部署与配置

工作台使用独立进程、独立数据卷和独立环境变量：

- `WIRE_MESH_KB_DB`：SQLite 文件路径。
- `WIRE_MESH_KB_ARCHIVE`：已归档 Markdown 报告目录。
- `WIRE_MESH_KB_ADMIN_TOKEN`：导入接口令牌（生产必填）。

运行：`uvicorn knowledge_workbench.app:app --host 0.0.0.0 --port 8090`。

首次导入：`python -m knowledge_workbench.import_reports /path/to/report-archive`。

生产演进：报告完成后由单独的归档任务复制 Markdown 文件到持久卷，再触发导入。该任务应捕获并记录自身异常，绝不可使主 Agent 的投递失败。

## 9. 验收标准

- 不修改 `api.py` 的调度、`main.py` 的投递流程、`collector.py` 或 `analyzer.py`。
- 能导入 Markdown 报告，重复运行不会生成重复数据。
- 可浏览、搜索、查看报告详情与趋势信号。
- 问答返回来源片段；无命中时不编造答案。
- 服务可在独立端口启动，数据库位于指定持久化路径。

## 10. 后续迭代

1. 用 PostgreSQL/pgvector 取代 SQLite，加入语义检索。
2. 接入受控的 DeepSeek 问答生成，并强制引用校验。
3. 引入明确来源和口径的外部行业指标（价格、出口、产能等），与“研报文本信号”分层展示。
4. 增加权限、收藏、订阅、分享和管理后台。
